# Overlay Fixed Pair 仕様

本書は固定ペア送出方式の正本である。
Atlas II（protocol/atlas-ii.md）の動的 Rect パケットはこの方式では使わない。
本番 `/bosai` は 2026-11-16 に本方式へ移行し、現行の送出方式は本方式である
（Atlas II センダーは `--no-a2-sender` で停止している）。

## 決定事項（2026-11-13 本人決定）

- 枠（本編を縮小して逆L字・門型の帯を確保する方式）は使わない。本編プレーヤーは
  そのまま再生し、その上に透過テロップを1枚重ねるだけにする。
- 送出サイズは **1920x2160、30fps** とする。
- 使用する表示要素は、まずは次の2つだけとする。
  1. 横型の緊急地震速報（EEW横型）
  2. 上部テロップ（地震情報・津波の各フレームに加え、長周期地震動の
     見出しフレームと階級フレームを含む）
- その他のデータ類・表示要素（津波ミニマップ、震度情報、縦型EEW 等）は、
  コードとデータとしては存在させたまま、使用しない（削除しない）。

## フレーム構成

1フレームは 1920x2160 の単一映像で、縦に2面を積む固定レイアウトとする。

| 領域 | 範囲 | 内容 |
| --- | --- | --- |
| 上段 | y = 0..1079（1920x1080） | テロップの RGB（不透明な黒背景に描いた色） |
| 下段 | y = 1080..2159（1920x1080） | テロップのαマスクをグレースケール（輝度）で描いたもの |

- 位置・寸法は固定であり、フレーム内に配置情報を一切埋め込まない。
  ヘッダー、CRC、セル符号化、パケット読み出しは存在しない。
- 色空間は従来どおり BT.709（tv range）に統一する。αマスクは輝度として
  送るため、受信側は下段の輝度をそのままαとして使う。
- テロップが何も表示されていないとき（待機時）は、原則として上段は全面黒、
  下段は全面黒（α=0）を送り、受信側は本編だけが見える状態になる。ただし
  受信確認のため、送出側は待機時に限り右下へ小さな「STANDBY」表示を
  上段RGB・下段αの双方へ合成する。環境変数 `OVERLAY_IDLE_MARK=0` で
  この表示を無効化できる（その場合は待機時も全面黒）。
- 当分の間の暫定措置として、送出側は全フレームの右下へ半透明
  （α=150）の「テスト中」表示を合成する。試験中の送出であることを
  受信側で常時判別できるようにするためで、運用者の明示の指示が
  あるまで継続する。環境変数 `OVERLAY_TEST_MARK=0` で無効化できる。
  待機時に STANDBY と併記する場合は STANDBY をその分だけ上へずらす。

## 受信側の合成（概要）

- 受信側は固定UVで上段・下段をサンプルし、`color = 上段RGB`、
  `alpha = 下段輝度` として本編の上にα合成する。
- ストリームが途絶・未接続のときはオーバーレイを表示しない（本編フル画面）。
  それ以外のフォールバック分岐は持たない。

## 送出側の構成

- レンダラーは `tools/capture_overlay.js`。Atlas と同じテロップページ
  （telop/atlas-1080.html、状態は共通の atlas-state スナップショット）を使い、
  使用する2要素だけを表示して 1920x1080 の RGBA（透過背景）で撮影する。
  EEW横型は本来の 1280x720 デザイン位置で撮影する（zoom 1.5）。
  予報級EEWのウィンドウ（#eew-forecast-window）は、上部テロップと
  左端・幅・拡大率を揃える。帯が表示されているときはその下へ配置し、
  3行目以降の高さに合わせて下へずらす。
  上部テロップ
  （#atlas-intensity）は、上マージン5%（54px）・左右マージン2.5%
  （48px、従来の5%から1段階拡大）を取った位置に置き、サイズを25%
  拡大する（`tools/capture_overlay.js` の `OVERLAY_CSS`。拡大後の表示幅が
  マージン内側に収まるよう、レイアウト幅は (1920−2×48)/1.25 = 1459.2px
  とする）。他の要素は描画しない（データとコードは残す）。
- 上部テロップの本文フォントは 40px、ルビ（rt）は 20px とし、比率を
  1:2 とする（サイズ体系「案1」）。行の高さは本文＋ルビで 60px とし、
  各ブロックは最大2行とする。津波1ブロックと地震最大3ブロックを並べ、
  コンテナの高さは最大8行と行間・余白に合わせる。ページ送りの詳細は
  [Atlas II状態モデル](../docs/08-atlas-state.md) を参照。
- 上部テロップの地名には総ルビを徹底する。震度行（市町村名・細分区域名）、
  長周期地震動の表示地名、津波の区域名（一覧・詳細の双方）と観測点名にルビを付ける。
  長周期地震動は気象庁の観測点と市区町村の対応に基づいて集約する。観測点名に
  市区町村名を含まない空港などは観測点名で表示する。
  ルビは各ブロックの1行目では本文の上、2行目では本文の下に付け、rt は 20px とする。
  読みは `lib/atlasData.js` が
  ルビマスターのセグメントを連結して名前→読みのマップを構築し、render／フレームに
  載せる。描画側（`telop/atlas-live.js`）は共通ヘルパーで付ける。読みデータの
  無い名前はルビなしでそのまま出す。
- ルビは基本モノルビ（漢字1字ごとに読みを付ける）とする。どうしても
  1字ずつに分割できない熟語だけ、その部分を熟語グループとして複数文字
  にまとめてルビを付ける。分割は描画時に推測・計算しない。ルビマスター
  `data/area_ruby_mono.json` に「名前→セグメント配列（[対象文字列, 読み]
  の組、対象の連結＝名前）」として確定データで収録する。地名の読みと
  ルビ分割はこのファイルで管理する。JSONは名前ごとに1行で記述する。
  読みの半角スペースは単語の区切りとして保持し、描画用セグメントからは除く。
  `lib/atlasData.js` は読みマップと併せてモノ分割マップ
  （フレームの `monoReadings`、render の `cityMonoReadings`）を載せ、
  共通ヘルパーはモノ分割がある名前はセグメントごとに描く。読みマップ
  だけに値がある名前は、その読みから漢字部分にルビを付ける。
  津波・長周期地震動の観測点名と読み、長周期地震動の観測点と市区町村の対応は
  [気象庁防災情報XML 個別コード表](https://xml.kishou.go.jp/tec_material.html) の
  2026年11月18日版を基にする。観測点と市区町村の対応は
  [観測点対応表](../data/jma_long_period_municipalities.json) で管理する。ルビ分割の候補には
  [KANJIDIC2](https://www.edrdg.org/kanjidic/kanjidic2.xml.gz)（EDRDG、CC BY-SA 4.0）の漢字別の読みを参照した。
- 札（バッジ）の高さは行の高さと同じ 60px とし、余白込みで本文＋ルビの
  高さに一致させる（枠 8px＋上下余白 6px＋ルビ 15px＋漢字 31px）。
  札の漢字は 31px、札のルビは 15px とし、札にもルビを振る（震度→
  しんど、大津波警報→おおつなみけいほう、津波警報→つなみけいほう、
  津波注意報→つなみちゅういほう、予想→よそう、長周期地震動→
  ちょうしゅうきじしんどう、階級→かいきゅう。読みは
  `telop/atlas-live.js` の固定マップ）。震度札の級サフィックス
  （弱→じゃく、強→きょう）にもルビを振る。札の中身（ルビ＋漢字の塊）は
  下寄せとし、漢字の下辺を本文の漢字の下辺に揃える。震度行の札列は
  248px のまま（padding 0 12px・border 4px は従来どおり）。黒の縁取り
  （-webkit-text-stroke）は全ての札で維持する。
- 札の色は業界の色ルールを優先し、気象庁「気象情報の配色に関する
  設定指針」（令和2年改訂）に従う。背景色は各表の色を使い、文字色と
  縁取りは視認性を確保するため背景に応じて次のようにする（2026-11-20 決定）。
  白文字（`#fff`）の札および上部テロップの札以外の文字（地名・ルビ・
  サマリー・時刻・高さなど）は SVG フィルタ（`#atlas-outline-body`）による
  不透明100%の丸縁黒枠と字間（本文 `0.06em`・ルビ `0.08em`・札文字 `0.04em`）
  を付け、黒文字（`#111`）の札は縁取りを付けない。震度札は同指針の表2-2（震度階級色）で背景色が震度ごとに
  変わる動的仕様とし、`telop/atlas-live.js` のマップから行の震度レベルで引く:
  震度1 `#f2f2ff`×黒（17.01）、震度2 `#00aaff`×白＋黒縁（2.56）、
  震度3 `#0041ff`×白＋黒縁（6.56）、震度4 `#fae696`×黒（15.13）、
  震度5弱 `#ffe600`×黒（14.90）、震度5強 `#ff9900`×白＋黒縁（2.14）、
  震度6弱 `#ff2800`×白＋黒縁（3.78）、震度6強 `#a50021`×白＋黒縁（8.01）、
  震度7 `#b40068`×白＋黒縁（6.69）。津波札は同指針の表1-2（台風・津波・
  噴火等の情報）: 大津波警報 `#c800ff`×白＋黒縁（4.29）、津波警報
  `#ff2800`×白＋黒縁（3.78）、津波注意報 `#faf500`×黒（16.30）、
  津波観測 `#ff00ff`×黒（6.02）、予想 `#fff`×黒（18.88）。
  長周期の現象札「長周期地震動」は `#ff2800`×白＋黒縁（3.78）、
  階級札は気象庁検討会資料の素案カラーで背景色を階級ごとに変える:
  階級1 `#faf500`×黒（16.30）、階級2 `#ff9900`×黒（8.82）、
  階級3 `#ff4b00`×白＋黒縁（3.36）、階級4 `#ff2800`×白＋黒縁（3.78）。
  津波スーパー（.tsunami-super）の種別セルと高さセルの色も同じ対応に揃える。
- 上部テロップの行割りは、バッジ幅とルビ幅を含めた行全体がレイアウト幅
  1459.2px（左右マージン 48px・字間 本文 `0.06em`・ルビ `0.08em`）に
  収まるよう文字数で制限する。実データ（公式サンプル全件）を
  新寸法・字間の CSS で Chromium 実レイアウト検証したところ、
  震度 24字では最大 +21.51px・津波一覧 28字では最大 +2.05px の
  はみ出しが生じたため、実サンプル全件ではみ出し 0件になる上限を
  それぞれ採った。
  震度行は 1行22字まで（区切り含む）。長周期地震動の階級ページは
  札と地名を別々の行に置く。地名は区切りを含めて1行28字までとし、
  地名単位でページを分ける（単一の地名が上限を超える場合はその地名
  だけで1行にする）。津波の種別別地名一覧は 1行27字まで（区切り含む）
  とし、区域数6件の上限と併用する（単一の区域名が27字を超える
  場合はその区域だけで1フレームにする）。
- `tools/overlay_sender.py` が `--state` 指定時に capture_overlay.js を
  子プロセスとして起動し、長さ前置PNGフレーム（capture_atlas.js と同じ
  フレーミング）を受け取る。`compose_overlay` で縮小せず
  1920x2160 に積み、最新フレームを 30fps で送り続けて ffmpeg から RTSP で送出する（静止画でも送出が途切れないようにするため）。
- `tools/atlas_service.py` は `--overlay-url` を指定したときだけ
  overlay-sender を子プロセスとして起動する。本番は `--no-a2-sender`
  と併用し、`rtsp://127.0.0.1:8554/bosai` へ送出する。
- MediaMTX 側は loopback からの publish 許可に `bosai` が必要
  （examples/mediamtx.production.example.yml 参照）。
- 音声: 送出には常時モノラル音声トラック（AAC 96k）を含む。
  `tools/eew_audio_stream.py` の EewAudioFeeder が無音を常時供給し、
  状態スナップショットを 100ms 間隔で監視する EewAudioTracker が
  警報級 EEW のときに音声パーツ（`telop/audio/eew/`）を再生する
  （Atlas II センダーと共通の仕組み）。`--state` なしで起動した場合は
  トラッカーを動かさず無音のみを流す。フィーダーや状態監視の失敗は
  プロセス終了として扱う（fail-fast。systemd が再起動する）。

## EEW の表示基準・投稿基準

- 表示基準（オーバーレイ。2026-11-15 本番運用モードへの移行で本人
  決定）: EEW は予想最大震度を問わず全件表示する。
- 投稿基準（Discord 情報 bot。2026-11-14 本人決定のまま変更なし）:
  予想最大震度が「不明・4・5弱・5強・6弱・6強・7」のいずれかなら
  投稿する（3以下は投稿しない）。表示基準とは分離しており、表示が
  全件になっても bot の投稿対象は広がらない。
- 予報級（警報でない）EEW は地図を出さず、画面上部（上部テロップと
  同じ上マージン、左端は横型ボックスと揃える）に置く角丸・
  半透明（黒50%）ウィンドウの2行テキストでのみ出す。書式は
  1行目「緊急地震速報(予報)[第N報]」（報数が取れなければ [第N報]
  なし）、2行目「<震源地名>で地震　最大震度<予想最大震度>
  　M<マグニチュード>　深さ<深さ>km」（要素間は全角スペース1つ、
  震源地名は電文のまま短縮しない）。予想最大震度が不明のときは
  「最大震度不明」、深さ0は「深さごく浅い」とし、マグニチュード・
  深さが取れない場合はその要素だけを省く。警報級は従来どおり
  地図つきボックス（横型・縦型）で出す。警報級ボックスが出ている
  間は、ウィンドウ要素をデータ行1行だけのコンパクト形
  （ストリップ）にして、警報級自身のデータ行を出す
  （ヘッダ行は出さない）。ストリップのデータ行は、ボックスの
  見出しに震源地名が書かれているため震源地名を省き
  「最大震度…　M…　深さ…km」の形にする。ウィンドウ・ストリップ
  とも、上部テロップのサマリーが同時表示されているときはその帯
  （予約高さ分）の下へずらして重ならないようにする。
  角丸・半透明・白文字のスタイルは
  ウィンドウと共通（compose は従来どおり両方を返し、出し分けは
  描画側で行う）。
- 基準は EEW レイヤーに適用する（情報源は問わない。予報級を運ぶのは
  実質 Wolfx のみ）。震度は内部表記（'5-'=5弱、'5+'=5強、'6-'=6弱、
  '6+'=6強）で、「不明」は予想最大震度が null の場合を指す。
- 実装: 判定の正本は `lib/eewAnnounce.js`（Node 側。表示判定は
  `eewDisplayMode`、投稿判定は `isEewPostable`）。ingest は
  `lib/atlasData.js` が render に `isWarning`・
  `maxInt`・`serial`・`magnitude`・`depthKm` を保持し、描画側
  `telop/atlas-live.js` が級で出し分ける（ページ埋め込みのため
  表示判定は同ファイルにも複製がある。投稿基準の震度集合は
  ブラウザ側には持たない）。
  /bosai（Atlas II）では `tools/atlas_ii.py` の `wire_state` が
  パケットの EEW 要素から予報級を外し（取消は級を問わず流す）、
  ウィンドウの描画はページ描画経由で atlas 画像に入る。
- Discord 情報 bot は `jma_server.js` が `lib/wolfxEewClient.js` で
  Wolfx へ直接接続して予報級を取り込み、既存の受け入れ口
  （EewTracker の重複管理）へ合流させる。投稿文は既存の EEW 投稿
  フォーマットそのまま。
