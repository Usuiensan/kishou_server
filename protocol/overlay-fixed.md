# Overlay Fixed Pair 仕様（原点回帰ブランチ）

本書は `feat/overlay-fixed-pair` ブランチにおける新しい送出方式の正本である。
Atlas II（protocol/atlas-ii.md）の動的 Rect パケットはこの方式では使わない。
本番 `/bosai` の現行方式は main の Atlas II であり、この方式は置き換え候補として
ブランチ上で検証する。マージ判断は別途行う。

## 決定事項（2026-11-13 本人決定）

- 枠（本編を縮小して逆L字・門型の帯を確保する方式）は使わない。本編プレーヤーは
  そのまま再生し、その上に透過テロップを1枚重ねるだけにする。
- 送出サイズは **1280x1440、2fps** とする。
- 使用する表示要素は、まずは次の2つだけとする。
  1. 横型の緊急地震速報（EEW横型）
  2. 上部2行テロップ（地震情報・津波の各フレームに加え、長周期地震動の
     見出しフレームと階級フレームを含む）
- その他のデータ類・表示要素（津波ミニマップ、震度情報、縦型EEW 等）は、
  コードとデータとしては存在させたまま、使用しない（削除しない）。

## フレーム構成

1フレームは 1280x1440 の単一映像で、縦に2面を積む固定レイアウトとする。

| 領域 | 範囲 | 内容 |
| --- | --- | --- |
| 上段 | y = 0..719（1280x720） | テロップの RGB（不透明な黒背景に描いた色） |
| 下段 | y = 720..1439（1280x720） | テロップのαマスクをグレースケール（輝度）で描いたもの |

- 位置・寸法は固定であり、フレーム内に配置情報を一切埋め込まない。
  ヘッダー、CRC、セル符号化、パケット読み出しは存在しない。
- 色空間は従来どおり BT.709（tv range）に統一する。αマスクは輝度として
  送るため、受信側は下段の輝度をそのままαとして使う。
- テロップが何も表示されていないとき（待機時）は、原則として上段は全面黒、
  下段は全面黒（α=0）を送り、受信側は本編だけが見える状態になる。ただし
  受信確認のため、送出側は待機時に限り右下へ小さな「STANDBY」表示を
  上段RGB・下段αの双方へ合成する。環境変数 `OVERLAY_IDLE_MARK=0` で
  この表示を無効化できる（その場合は待機時も全面黒）。
- 当分の間の暫定措置として、送出側は全フレームの右下へ半透明
  （α=150）の「テスト中」表示を合成する。試験中の送出であることを
  受信側で常時判別できるようにするためで、運用者の明示の指示が
  あるまで継続する。環境変数 `OVERLAY_TEST_MARK=0` で無効化できる。
  待機時に STANDBY と併記する場合は STANDBY をその分だけ上へずらす。

## 受信側の合成（概要）

- 受信側は固定UVで上段・下段をサンプルし、`color = 上段RGB`、
  `alpha = 下段輝度` として本編の上にα合成する。
- ストリームが途絶・未接続のときはオーバーレイを表示しない（本編フル画面）。
  それ以外のフォールバック分岐は持たない。

## 送出側の構成

- レンダラーは `tools/capture_overlay.js`。Atlas と同じテロップページ
  （telop/atlas-1080.html、状態は共通の atlas-state スナップショット）を使い、
  使用する2要素だけを表示して 1920x1080 の RGBA（透過背景）で撮影する。
  EEW横型は本来の 1280x720 デザイン位置へ戻し（zoom 1.5）。予報級
  EEW のウィンドウ（#eew-forecast-window）も同じ位置・同じ zoom で
  撮影する。警報級ボックス表示中のストリップ形（同要素のクラス
  strip）も同じ zoom のまま、上部テロップと同じ上マージンへ移して
  撮影する（below-summary 時は帯の下。位置の内訳は
  `tools/capture_overlay.js` の `OVERLAY_CSS` 冒頭コメント参照）。
  上部2行テロップ
  （#atlas-intensity）は、上・左・右に画面の5%のマージン（1920x1080 の
  撮影キャンバスで上54px・左右96px）を取った位置に置き、サイズを25%
  拡大する（`tools/capture_overlay.js` の `OVERLAY_CSS`。拡大後の表示幅が
  マージン内側に収まるよう、レイアウト幅は (1920−2×96)/1.25 = 1382.4px
  とする）。他の要素は描画しない（データとコードは残す）。
- 上部テロップの本文フォントは 36px とする。これは緊急地震速報の
  見出し文（「…で地震 強い揺れに警戒」）と実送出で同サイズにするため
  である。EEW 見出しの定義は `telop/eew.html` の `#headline` で 29px
  （fitHeadline の基準値も 29px）で、オーバーレイでは zoom 1.5 →
  複合 2/3 縮小を通り、複合フレーム上で 29px 相当に描かれる。
  実フレーム計測では、本文 52px のとき字高 38px（複合）に対し
  EEW 見出しは字高 26px（複合）で、比率 26/38 ≒ 0.68 から
  52 × 0.68 ≒ 35.4 → 36px を採った。札（バッジ）のフォントは
  変更しない（津波・長周期 58px、震度 66px のまま）。
- 上部テロップの地名には総ルビを徹底する。震度行（市町村名・細分区域名）、
  長周期地震動の観測点名、津波の区域名（一覧・詳細の双方）にルビを付ける。
  ルビは全行とも本文の上（ruby-position:over）に統一し、rt は 30px とする。
  行の高さは 100px のまま（36px 本文＋30px ルビ＋余白）とし、上部テロップの
  コンテナは 2行分で 200px とする。読みは `lib/atlasData.js` が
  `data/area_ruby.json` から名前→読みのマップを構築して render／フレームに
  載せ、描画側（`telop/atlas-live.js`）は共通ヘルパーで付ける。読みデータの
  無い名前はルビなしでそのまま出す。
- ルビは基本モノルビ（漢字1字ごとに読みを付ける）とする。どうしても
  1字ずつに分割できない熟語だけ、その部分を熟語グループとして複数文字
  にまとめてルビを付ける。分割は描画時に推測・計算しない。ルビマスター
  `data/area_ruby_mono.json` に「名前→セグメント配列（[対象文字列, 読み]
  の組、対象の連結＝名前、読みの連結＝`data/area_ruby.json` のグループ
  読みの連結）」として確定データで収録し、描画はそれをそのまま使う。
  `lib/atlasData.js` は読みマップと併せてモノ分割マップ
  （フレームの `monoReadings`、render の `cityMonoReadings`）を載せ、
  共通ヘルパーはモノ分割がある名前はセグメントごとに描き、無い名前は
  従来のグループルビへフォールバックする。マスターの再生成は
  `node tools/build_area_ruby_mono.js` で行い、漢字ごとの読み候補は
  KANJIDIC2 由来の `tools/kanji_readings.json` を候補生成にだけ使う
  （最終的な分割は連結検証を通ったものだけがマスターに残る）。
- 札（バッジ）は一回り大きくする。津波・長周期のバッジは height 80px・
  フォント 58px、震度バッジは height 84px・フォント 66px とし、震度行の
  札列は 248px とする（padding 0 12px・border 4px は従来どおり）。
- 上部テロップの行割りは、バッジ幅とルビ幅を含めた行全体がレイアウト幅
  1382.4px に収まるよう文字数で制限する。本文 36px では本文だけなら
  どの列にも余裕がある（震度行の地名列 1112.4px ÷ 36 ≒ 30.9字分、
  長周期の地名列 752.4px ÷ 36 ≒ 20.9字分、津波一覧の区域名列
  1038.4px ÷ 36 ≒ 28.8字分）が、読みは漢字より長く（例: 北海道
  太平洋沿岸中部 10字→読み21字、大崎市古川大崎 7字→読み13字）、
  30px のルビ側が幅を決める。実データ（公式サンプル全件、震度・
  長周期は実電文コーパスも含む）の全行を Chromium 実レイアウトで
  検証したところ、従来上限（震度21字・長周期14字・津波一覧19字）
  では、震度 14/2,233行（列幅を最大約31px超）、長周期 1/9行
  （約12px超）、津波一覧 19/361フレーム（最大約65px超）が列幅を
  はみ出したため、はみ出し0件になる上限へそれぞれ1字下げた。
  なお同検証で、隣り合うルビ同士の重なりは全行で0件だった
  （Chromium はルビを読み幅まで広げるため、超過は行末側の
  はみ出しとして現れる）。
  震度行は、札列 248px＋gap 22px を除いた地名列 1112.4px に対し
  1行20字まで（区切り含む）。長周期地震動の階級行は、バッジ2個
  （「長周期地震動」6字＋「階級N」3字、いずれも 58px＝522px、
  padding/border 各32px×2＝64px、gap 22px×2＝44px、計630px）を
  除いた地名列 752.4px に対し 1行13字まで（区切り含む）とし、
  地名単位で改行して2行ずつページ送りする（単一の地名が13字を
  超える場合はその地名だけで1行にする）。津波の種別別地名一覧は、
  種別バッジ（最大の「大津波警報」5字×58px＋padding 24px＋border
  8px＝322px、gap 22px）を除いた区域名列 1038.4px に対し
  1行18字まで（区切り含む）とし、区域数6件の上限と併用する
  （単一の区域名が18字を超える場合はその区域だけで1フレームにする）。
- `tools/overlay_sender.py` が `--state` 指定時に capture_overlay.js を
  子プロセスとして起動し、長さ前置PNGフレーム（capture_atlas.js と同じ
  フレーミング）を受け取る。`compose_overlay` で 1280x720 へ縮小して
  1280x1440 に積み、最新フレームを 2fps で送り続けて ffmpeg から RTSP で送出する（静止画でも送出が途切れないようにするため）。
- `tools/atlas_service.py` は `--overlay-url` を指定したときだけ
  overlay-sender を子プロセスとして起動する。本番は
  `rtsp://127.0.0.1:8554/bosai-overlay` へ送出する（`/bosai` の Atlas II
  送出は従来どおりで、本方式と並行する）。
- MediaMTX 側は loopback からの publish 許可に `bosai-overlay` が必要
  （examples/mediamtx.production.example.yml 参照）。

## EEW の発表基準（2026-11-14 本人決定）

- EEW の予想最大震度が「不明・4・5弱・5強・6弱・6強・7」のいずれかなら
  全体通知する（3以下は通知しない）。出し先はオーバーレイ
  （/bosai・/bosai-overlay）と Discord 情報 bot の両方。
- 予報級（警報でない）EEW は地図を出さず、横型ボックスと同じ位置
  （左上隅を合わせ、ボックスの表示領域内に収める）に置く角丸・
  半透明（黒50%）ウィンドウの2行テキストでのみ出す。書式は
  1行目「緊急地震速報(予報)[第N報]」（報数が取れなければ [第N報]
  なし）、2行目「<震源地名>で地震　最大震度<予想最大震度>
  　M<マグニチュード>　深さ<深さ>km」（要素間は全角スペース1つ、
  震源地名は電文のまま短縮しない）。予想最大震度が不明のときは
  「最大震度不明」、深さ0は「深さごく浅い」とし、マグニチュード・
  深さが取れない場合はその要素だけを省く。警報級は従来どおり
  地図つきボックス（横型・縦型）で出す。警報級ボックスが出ている
  間は、ウィンドウ要素をデータ行1行だけのコンパクト形
  （ストリップ）にして画面上部へ移し、警報級自身のデータ行を出す
  （ヘッダ行は出さない）。ストリップのデータ行は、ボックスの
  見出しに震源地名が書かれているため震源地名を省き
  「最大震度…　M…　深さ…km」の形にする。ストリップは上部テロップと同じ上
  マージンに置き（左端はウィンドウと揃える）、上部テロップの
  サマリーが同時表示されているときはその帯（予約高さ分）の下へ
  ずらして重ならないようにする。角丸・半透明・白文字のスタイルは
  ウィンドウと共通（compose は従来どおり両方を返し、出し分けは
  描画側で行う）。
- 基準は EEW レイヤーに適用する（情報源は問わない。予報級を運ぶのは
  実質 Wolfx のみ）。震度は内部表記（'5-'=5弱、'5+'=5強、'6-'=6弱、
  '6+'=6強）で、「不明」は予想最大震度が null の場合を指す。
- 実装: 判定の正本は `lib/eewAnnounce.js`（Node 側。bot の投稿判定と
  共通）。ingest は `lib/atlasData.js` が render に `isWarning`・
  `maxInt`・`serial`・`magnitude`・`depthKm` を保持し、描画側
  `telop/atlas-live.js` が級で出し分ける（ページ埋め込みのため
  判定集合は同ファイルにも複製がある）。
  /bosai（Atlas II）では `tools/atlas_ii.py` の `wire_state` が
  パケットの EEW 要素から予報級を外し（取消は級を問わず流す）、
  ウィンドウの描画はページ描画経由で atlas 画像に入る。
- Discord 情報 bot は `jma_server.js` が `lib/wolfxEewClient.js` で
  Wolfx へ直接接続して予報級を取り込み、既存の受け入れ口
  （EewTracker の重複管理）へ合流させる。投稿文は既存の EEW 投稿
  フォーマットそのまま。
