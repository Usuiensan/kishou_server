# Overlay Fixed Pair 仕様（原点回帰ブランチ）

本書は `feat/overlay-fixed-pair` ブランチにおける新しい送出方式の正本である。
Atlas II（protocol/atlas-ii.md）の動的 Rect パケットはこの方式では使わない。
本番 `/bosai` の現行方式は main の Atlas II であり、この方式は置き換え候補として
ブランチ上で検証する。マージ判断は別途行う。

## 決定事項（2026-11-13 本人決定）

- 枠（本編を縮小して逆L字・門型の帯を確保する方式）は使わない。本編プレーヤーは
  そのまま再生し、その上に透過テロップを1枚重ねるだけにする。
- 送出サイズは **1280x1440、2fps** とする。
- 使用する表示要素は、まずは次の2つだけとする。
  1. 横型の緊急地震速報（EEW横型）
  2. 上部2行テロップ
- その他のデータ類・表示要素（津波ミニマップ、震度情報、縦型EEW 等）は、
  コードとデータとしては存在させたまま、使用しない（削除しない）。

## フレーム構成

1フレームは 1280x1440 の単一映像で、縦に2面を積む固定レイアウトとする。

| 領域 | 範囲 | 内容 |
| --- | --- | --- |
| 上段 | y = 0..719（1280x720） | テロップの RGB（不透明な黒背景に描いた色） |
| 下段 | y = 720..1439（1280x720） | テロップのαマスクをグレースケール（輝度）で描いたもの |

- 位置・寸法は固定であり、フレーム内に配置情報を一切埋め込まない。
  ヘッダー、CRC、セル符号化、パケット読み出しは存在しない。
- 色空間は従来どおり BT.709（tv range）に統一する。αマスクは輝度として
  送るため、受信側は下段の輝度をそのままαとして使う。
- テロップが何も表示されていないとき（待機時）は、原則として上段は全面黒、
  下段は全面黒（α=0）を送り、受信側は本編だけが見える状態になる。ただし
  受信確認のため、送出側は待機時に限り右下へ小さな「STANDBY」表示を
  上段RGB・下段αの双方へ合成する。環境変数 `OVERLAY_IDLE_MARK=0` で
  この表示を無効化できる（その場合は待機時も全面黒）。

## 受信側の合成（概要）

- 受信側は固定UVで上段・下段をサンプルし、`color = 上段RGB`、
  `alpha = 下段輝度` として本編の上にα合成する。
- ストリームが途絶・未接続のときはオーバーレイを表示しない（本編フル画面）。
  それ以外のフォールバック分岐は持たない。

## 送出側の構成

- レンダラーは `tools/capture_overlay.js`。Atlas と同じテロップページ
  （telop/atlas-1080.html、状態は共通の atlas-state スナップショット）を使い、
  使用する2要素だけを表示して 1920x1080 の RGBA（透過背景）で撮影する。
  EEW横型は本来の 1280x720 デザイン位置へ戻し（zoom 1.5）、上部2行テロップ
  （#atlas-intensity）は上端・全幅に置く。他の要素は描画しない
  （データとコードは残す）。
- `tools/overlay_sender.py` が `--state` 指定時に capture_overlay.js を
  子プロセスとして起動し、長さ前置PNGフレーム（capture_atlas.js と同じ
  フレーミング）を受け取る。`compose_overlay` で 1280x720 へ縮小して
  1280x1440 に積み、最新フレームを 2fps で送り続けて ffmpeg から RTSP で送出する（静止画でも送出が途切れないようにするため）。
- `tools/atlas_service.py` は `--overlay-url` を指定したときだけ
  overlay-sender を子プロセスとして起動する。本番は
  `rtsp://127.0.0.1:8554/bosai-overlay` へ送出する（`/bosai` の Atlas II
  送出は従来どおりで、本方式と並行する）。
- MediaMTX 側は loopback からの publish 許可に `bosai-overlay` が必要
  （examples/mediamtx.production.example.yml 参照）。
